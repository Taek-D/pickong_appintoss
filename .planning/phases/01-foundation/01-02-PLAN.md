# Plan 01-02: Toss Login

## Goal
사용자가 S-ONB → S-LOGIN을 통과해 토스 로그인 후 user_key를 영속 보유하고, 끊김 발생 시 바텀시트 없이 자동 재연결된다.

## Requirements covered
- AUTH-01 (토스 로그인 강제 + user_key 영속)
- AUTH-02 (끊김 자동 재연결)

## Steps

### 1. S-ONB 화면 (`src/screens/Onboarding.tsx`)
- 슬라이드 3장 (PRD §7.2 카피 인용):
  - 1p: "좋아한 것을 그냥 지나치기 아쉬울 때"
  - 2p: "문구·굿즈·간식을 도감 한 칸에 담아요"
  - 3p: "이번 달 내 취향이 캐릭터로 돌아와요"
- BottomCTA: "시작하기" → `/login`
- swipe gesture (touch + mouse drag) + 진행 dot 인디케이터 3개
- 권한 요청 0건
- Analytics: `onb_view_step`(step), `onb_press_start`
- Storage `onboarding_completed`가 true면 `/login` 또는 `/`로 자동 라우팅 (라우터 가드)

### 2. S-LOGIN 화면 (`src/screens/Login.tsx`)
- Top: 브랜드 로고 + "픽콩"
- Body: 헤드라인 "픽콩에서 내 도감을 시작해 볼까요?" + 서브 "토스로 로그인하면 기록이 안전하게 이어져요" + 일러스트 placeholder
- BottomCTA: "토스로 시작하기"
- 로딩 상태: 버튼 disabled + spinner
- 실패 토스트: "지금은 처리가 안 됐어요. 잠시 후 다시 시도해 볼까요?"
- Analytics: `login_view`, `login_press_start`, `login_success`(is_first_login, entry_source), `login_cancel`, `login_fail`(error_code)

### 3. 클라이언트 로그인 훅 (`src/lib/auth.ts`)
- `useTossLogin()` 훅:
  - `appLogin()` 호출 → 인가 코드 수신
  - 백엔드 `POST /auth/exchange { code }` → `{ user_key, is_first_login }` 수신
  - cookie 자동 세팅 (백엔드 Set-Cookie)
  - Storage `user_key:current` 캐시
  - 세션 store 갱신
  - 진입 source(`entry_source`)는 URL 쿼리(`?from=share`)로 분기
- `useEnsureLoggedIn()` 가드:
  - 페이지 마운트 시 `GET /auth/me` 호출
  - 401 → `/login` 라우팅 + 자동 재연결 안내(토스트 not 바텀시트)
  - 200 → 세션 hydrate
- 재연결 토스트 카피: "토스 로그인을 다시 연결해 볼까요?"

### 4. 백엔드 `/auth/exchange` (`server/src/routes/auth.ts`)
- POST body: `{ code: string }`
- 흐름:
  1. mTLS toss-client로 `generateOauth2Token({ code })` → `{ access_token, refresh_token, expires_in }`
  2. `loginMe({ access_token })` → `{ user_key }`
  3. `accounts` upsert (user_key PK, last_login_at = now())
  4. is_first_login = (created_at === last_login_at) 판정
  5. 세션 cookie 발급 (HMAC sealed `{ user_key, exp }`, httpOnly, sameSite=Lax)
- Response: `{ user_key, is_first_login, nickname }`
- 에러: 토스 응답 실패 → `{ error_code: 'toss_unavailable' }` 502
- mTLS 미설정 시 mock: 임의 user_key 발급, accounts upsert 동일

### 5. 백엔드 `/auth/me`
- GET, 인증 미들웨어가 cookie 검증
- 200 `{ user_key, nickname }` 반환
- 401 `{ error_code: 'unauthenticated' }`

### 6. 회원 탈퇴 placeholder (Phase 2 풀구현)
- `server/src/routes/account.ts`에 `DELETE /account` 스켈레톤만 (501 not_implemented)

### 7. 라우팅 분기 (PRD §6.2 6 케이스)
- 미로그인 + `/`: → `/onb` (onboarding 미완) or `/login`
- 미로그인 + `/login`: 정상
- 로그인 + nickname null + `/`: → `/nick`
- 로그인 + nickname 있음 + `/`: → 메인
- `/card/:hash`로 진입 (Phase 2): `/login`으로 리다이렉트 + entry_source=share 표식

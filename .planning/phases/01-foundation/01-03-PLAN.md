# Plan 01-03: Nickname Input

## Goal
로그인 직후 닉네임 미입력 사용자가 S-NICK 화면에서 한글 완성형 + 영문 + 숫자 1~10자만 입력해 1회 등록하고, 5종 에러 토스트가 정확히 분기된다.

## Requirements covered
- AUTH-03 (닉네임 1회 입력 강제 + 정규식)
- AUTH-04 (추천 칩 6개 고정)

## Steps

### 1. S-NICK 화면 (`src/screens/Nickname.tsx`)
- 진입 가드: 로그인 + nickname == null
- Top: "어떻게 부를까요?"
- Body:
  - 서브 "친구에게 카드를 공유할 때 이렇게 보여요"
  - TextField (1~10자, placeholder "닉네임 입력")
  - 추천 칩 6개 (가로 스크롤): 귀염콩 / 굿즈콩 / 문구콩 / 덕질콩 / 픽콩러 / 수집콩
  - 칩 클릭 → 텍스트 필드에 즉시 채움 + Analytics nick_press_suggest
- BottomCTA "이 이름으로 시작할게요" (값 비면 disabled)
- KeyboardAboveView 활성 (CTA가 키보드 위)

### 2. 입력 단계 자동 무시 (PRD §10.6 step 1)
- onChange handler에서 매 입력 즉시 다음 문자 제거:
  - 이모지 (Surrogate pair)
  - 특수문자 (한글/영문/숫자 외)
  - 자모 단독 (ㄱ-ㅎ, ㅏ-ㅣ 단독)
  - 공백
- 차단 시 Analytics `nick_input_blocked_char(reason)`

### 3. 정규식 (`shared/src/constants.ts`)
- `NICKNAME_REGEX = /^[가-힣A-Za-z0-9]{1,10}$/`
- `JAMO_ONLY_REGEX = /^[ㄱ-ㅎㅏ-ㅣ]+$/`

### 4. 저장 흐름
- BottomCTA 클릭:
  - 클라 1차 검증 (정규식)
  - `POST /account/nickname { nickname }` 호출
  - 200 → 세션 store nickname 갱신 + Storage `nickname:current` + 다음 라우트 (entry_source가 share면 `/card/:hash`, 아니면 `/`)
  - 4xx → 토스트 분기

### 5. 5종 에러 토스트 (PRD §16 인용)
| error_code | 토스트 카피 |
|---|---|
| `length` (빈값/초과) | 닉네임을 한 글자 이상 적어 볼까요? |
| `blocked_char` | 닉네임은 한글, 영문, 숫자만 쓸 수 있어요 |
| `jamo_only` | 자음·모음만으로는 닉네임을 만들 수 없어요. 완성된 글자로 적어 볼까요? |
| `forbidden` | 이 닉네임은 쓸 수 없어요. 다른 이름으로 바꿔 볼까요? |
| `network` | 인터넷 연결을 확인하고 다시 시도해 볼까요? |

### 6. 백엔드 `POST /account/nickname` (`server/src/routes/account.ts`)
- 인증 미들웨어 통과 (cookie)
- body: `{ nickname: string }`
- Zod schema: `z.string().regex(NICKNAME_REGEX)`
- 추가 검증:
  1. JAMO_ONLY_REGEX 매칭 → `error_code: 'jamo_only'`
  2. 금칙어 사전 검증 (01-04에서 wired) → `error_code: 'forbidden'`
- DB: `UPDATE accounts SET nickname=$1 WHERE user_key=$2` (UNIQUE 제약 없음 — 중복 허용)
- Response: `{ ok: true }` 또는 `{ error_code }`
- Analytics: `nick_save_success` / `nick_save_fail(error_code)`

### 7. PATCH /account/nickname (Phase 2 use)
- 같은 라우트, PATCH 메서드 추가하되 내부에서 현재 달 active 카드 nickname_snapshot 동기화 — Phase 2에서 wired (현재는 placeholder)

### 8. Analytics 이벤트
- `nick_view(entry_source)`
- `nick_press_suggest(suggestion)`
- `nick_input_blocked_char(reason: emoji|special_char|space|jamo_only|length)`
- `nick_press_save(length, used_suggestion: boolean)`
- `nick_save_success`
- `nick_save_fail(error_code)`

## Acceptance Criteria
- [ ] 추천 칩 6개 1탭으로 입력 완료 가능 (12초 SLA 기여)
- [ ] 이모지·특수문자·자모 단독·공백 입력 시 자동 무시 + 차단 이벤트 적재
- [ ] 정규식 통과 시 백엔드 저장 → 다음 라우트
- [ ] 5종 에러 토스트가 PRD §16 카피 그대로 노출
- [ ] BottomCTA가 키보드 위 표시 (KeyboardAboveView)
- [ ] 한글 9자, 10자 케이스 (경계값) 정상 처리
- [ ] 한글 11자 입력 차단
- [ ] 백엔드 응답 latency ≤ 300ms (PRD §10.11)
